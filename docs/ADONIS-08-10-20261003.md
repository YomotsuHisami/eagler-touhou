## 历史核对得出的迁移方法

先阅读历史和原始分析，再写 [完整迁移检查表](playbooks/adonis-adaptation.md)，之后才实施 08／10。核对的主要历史为《实现延迟处理机制》《总结 TH09 观战修复与验收》《排查联机状态分叉》，以及用户提供的 `D:/Downloads/PoFV_Adonis_VPatch_全包静态分析.md` 第 4／6 节。该分析作为证据使用。

历史中的固定 4f／2f、额外 `+1` 帧、默认启用回滚等方案已被后续决定取代。当前迁移遵循以下顺序，每一步都有独立验收条件：

1. **确定产品基线和所有者。** 对照已发布的 MP 修订，记录公共库、原生构建身份和已有改动；普通版与 MP 版的源码、存档和发布代次分别处理。先读联机、回滚和运行包主 playbook，涉及录像和呈现时再读对应 playbook。
2. **先完成原生能力，再开放前端。** 分清协议、原生 Runtime、浏览器传输、房间与 Relay 的责任。缺少实测能力的旧 Runtime 明确拒绝，不能用前端猜出的数值冒充已协商参数。
3. **先准备世界，再测实际输入链路。** 字体、资源和世界加载完成后，使用本局最终选中的 RTC／Relay 输入通道测量；逻辑第零帧必须等测量提交及原生会话屏障结束。高精度本地单调时钟计时，不相减不同设备的时钟。
4. **复现测量算法和整数边界。** 发送 1～129 轮探测，相邻新轮相对等待 16 ms，每次 pump 最多开始一轮；取 10～129 共 120 个样本，最后等待 16+200 ms。每条必需链路至少 96 个有效样本，保留最小／平均／最大值、P95 式统计、成功和丢失数量。隐藏、明显调度中断、换路和不足样本明确失败，不静默退回估算。
5. **把测量与策略作为全员事务。** 绑定人数、席位、会话代次、seed、玩法／构建 ABI、模式、自动／手动和削减上限；全员核验提议、接受、提交及确认。三人局必须覆盖 P2↔P3 等所有输入链路，不能只测主机；覆盖丢包、重发、迟到确认和早到的原生 HELLO。
6. **分清延迟、预测和完整回滚窗口。** 自动纯延迟 D=B、P=0；自动混合模式目标 D=1，最多削减 2f。手动 D 保持权威。P 不缩短回滚历史，也不是强制每帧预测；纯延迟应实际绕过世界快照和重演。相位修正只调整墙钟调度，并扣除 P 的允许提前量，避免把削掉的延迟重新等回来。
7. **守住输入和副作用边界。** 每个 N+D 只采一次设备输入，重试／重演不重采；状态相关的触控与菜单解释不能提前到尚未纠正的预测状态。原生固定 60 Hz 逻辑及带副作用的 Draw 保持原语义；声音、文件、确认录像与观战输出按确认边界提交。
8. **分别接入观战、录像、房间和发布包。** 观战先收到固定时序元数据，再收到零帧；确认输入不再追加 D。上传断开、积压与无进展只影响观战，发送和追帧分别设预算。前端只显示当前 epoch／run／host 的原生结果，测试主客权限、重新进房、语言和窄屏。组件、真实浏览器、真实 Launcher、Release 包、公开部署属于不同证据，不能相互代替。

检查表还记录了本轮实际遇到的测试陷阱：WASM 导出可能扩容，须先取指针再取 `memory.buffer`；模拟进度不等于录像已归档进度；观战必须走真实入场流程；短暂显示的测量结果应在连接阶段采集。

当前整数转换：

```text
B = max(1, ceil(floor(max_required_RTT_us / 2) * 60 / 1000000))
纯延迟自动：D = B，P = 0
混合自动：P = min(协商的 1f／2f 削减上限, B - 1)，D = B - P
```

没有额外 `+1`。手动模式保留所选 D。开局参数固定，局内质量显示的 RTT 不重新改写本局 D。RTT/2 是对称链路估计，不能直接等同于体感或输入到画面的总延迟。
